## فولیو چیست؟

**Folio (فولیو)** یک استودیوی نوشتن کتاب با هوش مصنوعی است که داده‌ها را روی دستگاه خودت نگه می‌دارد (local-first).

تو این‌ها را می‌دهی:

- عنوان و توضیح کتاب
- outline کامل (فصل‌ها و بخش‌ها)
- سبک نوشتن و مخاطب
- زبان (فارسی، انگلیسی، عربی، …)
- تنظیمات صفحهٔ ورد (فونت، قطع، جلد، فهرست)
- **ارائه‌دهندهٔ AI خودت** (ابری یا محلی)

برنامه کتاب را **فصل‌به‌فصل** می‌نویسد، glossary و خلاصهٔ فصل‌ها را زنده نگه می‌دارد تا فصل‌های بعدی تناقض نداشته باشند، اجازهٔ توقف / ادامه / ویرایش / تولید دوباره می‌دهد، یک مرحلهٔ کنترل کیفیت اجرا می‌کند و در پایان یک فایل **مایکروسافت ورد (`.docx`)** حرفه‌ای با Heading واقعی، فهرست مطالب، شماره صفحه و RTL خروجی می‌گیرد.

این یک جعبهٔ سادهٔ «یک پرامپت بده، کل کتاب را بگیر» نیست. یک لایهٔ جدا به نام **AI Engine** جلوی استودیو نشسته است. فولیو فرض نمی‌کند Grok، OpenAI یا هیچ فروشندهٔ دیگری از قبل وجود دارد. اگر هیچ مدلی وصل نباشد، اولین صفحه ویزارد اتصال است.

کلمهٔ **Folio** از لاتین / ایتالیایی آمده: برگ بزرگ کتاب، یا جلد حرفه‌ای یک نسخهٔ خطی.

جریان ایده‌آل:

```text
وصل کردن AI Engine
      ↓
ساخت کتاب (عنوان → outline → صدا → صفحه)
      ↓
تولید فصل‌به‌فصل (ایجنت‌ها + حافظه)
      ↓
بازبینی / بازنویسی بخش‌ها
      ↓
کنترل کیفیت
      ↓
خروجی .docx
```

## نصب و اجرا

```bash
git clone https://github.com/AmirHKD1386/folio-ai-book-studio.git
cd folio-ai-book-studio
npm install
npm run dev
```

صبر کن تا `npm install` **تمام شود**. وسط کار با Ctrl+C قطع نکن.

بعد در مرورگر برو به **http://localhost:8080**

| دستور | کار |
|--------|------|
| `npm run dev` | سرور توسعه روی پورت **۸۰۸۰** |
| `npm run build` | ساخت نسخهٔ نهایی |
| `npm run preview` | پیش‌نمایش نسخهٔ نهایی |
| `npm run typecheck` | بررسی TypeScript |
| `npm test` | تست‌ها |
| `npx vite dev --host 0.0.0.0 --port 8080` | اجرای مستقیم Vite (مناسب ویندوز) |

اگر پورت ۸۰۸۰ اشغال است:

```bash
npx vite dev --host 0.0.0.0 --port 5173
```

## ویندوز: خطای spawn vite ENOENT

روی ویندوز این خطا زیاد دیده می‌شود:

```text
[with-app-env] failed to run vite: spawn vite ENOENT
```

**علت.** دستور `npm run dev` یک اسکریپت Node را اجرا می‌کند و آن اسکریپت سعی می‌کند فایل `vite` را جداگانه روشن کند. ویندوز اغلب مسیر `node_modules\.bin\vite` را در این حالت پیدا نمی‌کند.

**راه‌حل ۱ — پیشنهادی.** بعد از یک `npm install` کامل، Vite را با npx اجرا کن:

```bat
cd C:\Users\<نام-کاربری>\Desktop\folio-ai-book-studio
npm install
npx vite dev --host 0.0.0.0 --port 8080
```

**راه‌حل ۲ — تغییر اسکریپت.** در `package.json` این را بگذار:

```json
"dev": "vite dev --host 0.0.0.0 --port 8080"
```

در این حالت خود npm مسیر `node_modules\.bin` را درست می‌کند.

**راه‌حل ۳ — نصب تمیز** اگر قبلاً `npm install` را قطع کرده‌ای:

```bat
rmdir /s /q node_modules
del package-lock.json
npm install
npx vite dev --host 0.0.0.0 --port 8080
```

وجود Vite را چک کن:

```bat
dir node_modules\.bin\vite.cmd
npx vite --version
```

اگر `vite.cmd` نیست، نصب کامل نشده.

## اولین ورود — وصل کردن هوش مصنوعی

تا وقتی حداقل یک ارائه‌دهنده وصل نشود و به ایجنت **Writer** اختصاص داده نشود، فولیو کتاب نمی‌نویسد.

1. برنامه را باز کن → **AI Engine** (یا بنر اولین اجرا).
2. یک پیش‌تنظیم انتخاب کن:
   - ابر سازگار با OpenAI
   - Ollama (محلی)
   - LM Studio (محلی)
   - سفارشی / روی سرور خودت
   - مدل تزریق‌شدهٔ پلتفرم (فقط اگر محیط از قبل یکی داشته باشد)
3. این فیلدها را پر کن: نام، Base URL، شناسهٔ مدل، کلید API، دما، حداکثر توکن، پنجرهٔ context، تعداد تلاش مجدد، محدودیت نرخ، تایم‌اوت، هدرهای سفارشی، سطح مسیریابی.
4. **Test connection** را بزن.
5. مدل‌ها را به ایجنت‌ها بده (یا **Auto-assign by tier**).
6. استراتژی را انتخاب کن: **Fast**، **Balanced** یا **Full desk**.
7. **Start studio**.

هر وقت خواستی از کتابخانه دوباره **AI Engine** را باز کن: Providers، Agents، Prompts، Memory، Usage.

## کلید API و مدل‌های محلی

فولیو با پروتکل **OpenAI Chat Completions** حرف می‌زند (`POST {baseUrl}/chat/completions`). هر سروری که این مسیر را پیاده کرده باشد کار می‌کند.

### الف) xAI Grok

1. برو به [https://console.x.ai](https://console.x.ai) و وارد شو.
2. بخش **API Keys** → **Create API Key**.
3. کلید را **همان لحظه** کپی کن (دوباره نشان داده نمی‌شود).
4. در فولیو → AI Engine → ابر سازگار با OpenAI:

| فیلد | مقدار |
|------|--------|
| Base URL | `https://api.x.ai/v1` |
| API key | کلید xAI خودت |
| Model | شناسهٔ روز از [docs.x.ai](https://docs.x.ai) (مثال: `grok-4`، `grok-4-fast`) |

مستندات: [xAI overview](https://docs.x.ai/docs/overview)

### ب) OpenAI

| فیلد | مقدار |
|------|--------|
| Base URL | `https://api.openai.com/v1` |
| API key | از [platform.openai.com/api-keys](https://platform.openai.com/api-keys) |
| Model | مثلاً `gpt-4.1`، `gpt-4o`، `gpt-4o-mini` |

### پ) OpenRouter (چند مدل با یک کلید)

| فیلد | مقدار |
|------|--------|
| Base URL | `https://openrouter.ai/api/v1` |
| API key | از [openrouter.ai/keys](https://openrouter.ai/keys) |
| Model | مثلاً `openai/gpt-4o-mini`، `anthropic/claude-sonnet-4` |

### ت) Ollama (رایگان و آفلاین)

1. از [https://ollama.com](https://ollama.com) نصب کن.
2. یک مدل چت بکش:

```bash
ollama pull llama3.2
ollama pull qwen2.5:7b
ollama pull mistral
```

3. سرور باید روشن باشد (`ollama serve` اگر خودش بالا نیست).
4. در فولیو **Ollama (local)** را انتخاب کن:

| فیلد | مقدار |
|------|--------|
| Base URL | `http://127.0.0.1:11434/v1` |
| API key | هر متنی (`ollama`) |
| Model | **دقیقاً** همان نامی که کشیدی، مثلاً `llama3.2` |

نام مدل باید با خروجی `ollama list` یکی باشد.

### ث) LM Studio (برنامهٔ گرافیکی محلی)

1. [LM Studio](https://lmstudio.ai) را نصب کن.
2. یک مدل چت داخل برنامه دانلود کن.
3. **Local server** را از تب Developer روی پورت **۱۲۳۴** روشن کن.
4. در فولیو **LM Studio (local)** را بزن:

| فیلد | مقدار |
|------|--------|
| Base URL | `http://127.0.0.1:1234/v1` |
| API key | `lm-studio` (یا خالی اگر سرور اجازه بدهد) |
| Model | شناسه‌ای که LM Studio نشان می‌دهد |

### ج) سفارشی / روی سرور خودت

vLLM، llama.cpp server، LocalAI، text-generation-webui و مشابه.

- Base URL باید به `/v1` ختم شود (فولیو خودش `/chat/completions` را اضافه می‌کند).
- شناسهٔ مدل را مطابق سرور بگذار.
- اگر میزبان هدر اجباری دارد (مثل `HTTP-Referer` برای OpenRouter) در Custom headers اضافه کن.

**هرگز کلید واقعی را داخل متن کتاب، outline یا ایشوی گیت‌هاب نگذار.**

## تست اتصال

دکمهٔ **Test connection** به ترتیب این‌ها را چک می‌کند:

1. **احراز هویت** — کلید / آدرس قبول می‌شود
2. **وجود مدل** — شناسهٔ مدل شناخته می‌شود
3. **تولید متن** — یک جواب کوتاه برمی‌گردد
4. **تأخیر** — زمان رفت‌وبرگشت

اگر شکست بخورد پیام واضح می‌آید (کلید غلط، مدل نیست، تایم‌اوت، شبکه، محدودیت نرخ) و می‌توانی **Retry** یا **Change provider** بزنی. استودیو تا وقتی Writer یک ارائه‌دهندهٔ سالم نداشته باشد قفل می‌ماند.

## ایجنت‌ها، مدل‌ها و استراتژی

به‌جای یک مدل که کل کتاب را بنویسد، فولیو چند نقش تخصصی دارد. هر ایجنت می‌تواند مدل **اصلی** و زنجیرهٔ **پشتیبان (fallback)** داشته باشد.

| ایجنت | کار | سطح پیشنهادی |
|--------|------|----------------|
| **Planner** | برنامه و beat sheet فصل | fast |
| **Curriculum** | ترتیب یادگیری و پیش‌نیاز | balanced |
| **Research** | نکته از brief — هرگز منبع جعلی نمی‌سازد | balanced |
| **Writer** | نثر قابل انتشار | balanced |
| **Math reviewer** | معادله و اثبات | reasoning |
| **ML connector** | مثال عملی یادگیری ماشین | balanced |
| **Reviewer** | بازبینی فنی / واقعی | reasoning |
| **Editor** | صدا، سبک، روان‌نویسی | fast |
| **QC** | تکرار، شکاف، تناقض | fast |
| **Formatter** | نکته‌های ساختار ورد | fast |

**Auto-assign by tier** ایجنت‌ها را به ارائه‌دهنده‌هایی که fast / balanced / reasoning علامت زده‌ای وصل می‌کند.

### استراتژی‌ها

| استراتژی | مراحل هر فصل | کی استفاده کنی |
|-----------|----------------|-----------------|
| **Fast** | فقط Writer | پیش‌نویس ارزان، مدل محلی |
| **Balanced** (پیش‌فرض) | Planner → Writer → Editor → QC | بیشتر کتاب‌ها |
| **Full desk** | Curriculum → Planner → Research → Writer → Math → ML → Reviewer → Editor → QC → Formatter | کتاب درسی و فنی |

اگر مدل اصلی خطا بدهد (محدودیت نرخ، تایم‌اوت، در دسترس نبودن)، فولیو خودکار سراغ فهرست پشتیبان می‌رود.

پرامپت‌ها در **AI Engine → Prompts** قابل ویرایش‌اند. متغیرها:

```text
{{book_title}}
{{book_description}}
{{chapter_title}}
{{chapter_outline}}
{{previous_context}}
{{writing_style}}
{{style_notes}}
{{language}}
{{audience}}
```

## ساخت کتاب از صفر تا صد

1. **کتابخانه** — نمونه (Sample) را باز کن تا سه پنل استودیو را ببینی، یا **New book** بزن.
2. **Brief** — عنوان، زیرعنوان، نویسنده، توضیح.
3. **Outline** — یک outline مارک‌داون بچسبان. فولیو `# فصل` و `## بخش` را درخت می‌کند. می‌توانی مقدمه / نتیجه‌گیری را با سوییچ اضافه کنی.
4. **Voice** — زبان (فارسی، انگلیسی، عربی، …)، سبک (آموزشی، دانشگاهی، داستانی، …)، مخاطب، یادداشت سبک.
5. **Engine** — نشان می‌دهد Writer از کدام ارائه‌دهنده استفاده می‌کند. اگر هیچی وصل نیست اول به AI Engine برو.
6. **Press** — فونت متن / تیتر، A4 یا Letter، جلد، فهرست مطالب، شماره صفحه، ارقام فارسی.
7. **Create** — پروژه در مرورگر ذخیره می‌شود و وارد استودیو می‌شوی.

نمونهٔ outline:

```markdown
# مقدمه
این کتاب برای چه کسی است.

# فصل ۱: اصول اولیه
## ایدهٔ اصلی
## یک مثال عملی

# فصل ۲: تمرین
## عادت روزانه
## اشتباه‌های رایج

# نتیجه‌گیری
دوشنبه صبح چه کار کنی.
```

برای هر بخش چند جمله کافی است؛ همان چیزی است که Writer می‌بیند.

## استودیو: نوشتن، بازبینی، تولید دوباره

سه پنل:

| پنل | کار تو |
|------|--------|
| **ساختار** (چپ) | پرش بین فصل‌ها و بخش‌ها؛ دیدن وضعیت تولید |
| **ویرایشگر** (وسط) | صفحه. آزاد ویرایش کن. ذخیرهٔ خودکار. تاریخچهٔ نسخه برای هر بخش |
| **دستیار** (راست) | تولید، بازنویسی، گسترش، کوتاه کردن، بهبود، ادامه، ساده‌سازی یا دستور سفارشی |

**Generate entire book** خط تولید را روی همهٔ بخش‌های خالی، به ترتیب، اجرا می‌کند. توقف / ادامه / لغو دارد. پیشرفت محلی ذخیره می‌شود تا اگر برنامه بسته شد پیش‌نویس نپرد.

می‌توانی **یک بخش** را دوباره بسازی بدون دست زدن به بقیه.

پنل کیفیت: امتیاز ساده (طول، بخش خالی، تکرار) به‌علاوهٔ عبور اختیاری ایجنت QC قبل از خروجی.

## خط تولید فصل

```text
Outline
  → بازبینی برنامهٔ درسی     (Full desk)
  → برنامه‌ریزی فصل
  → یادداشت پژوهش            (Full desk)
  → نوشتن
  → بازبینی ریاضی            (Full desk)
  → مثال یادگیری ماشین       (Full desk)
  → بازبینی فنی              (Full desk)
  → ویرایش سبک
  → کنترل کیفیت
  → نکتهٔ قالب‌بندی          (Full desk)
  → خروجی DOCX
```

هر مرحله نوار پیشرفت، لاگ، Retry و Pause دارد. خطاها دکمهٔ **Retry / resume** و **Change provider** نشان می‌دهند.

## حافظهٔ کتاب

قبل از هر فصل فولیو یک **بستهٔ فشرده** برمی‌دارد، نه کل کتاب:

- خلاصهٔ فصل‌های قبلی
- واژه‌نامه / اصطلاحات
- شخصیت‌ها و نام‌های تکرارشونده
- مفاهیم مهم
- یادداشت سبک
- فقط ارجاع‌های تأییدشده (هرگز DOI یا URL ساختگی)

همین بسته داخل `{{previous_context}}` می‌رود. در **AI Engine → Memory** می‌توانی ببینیش.

## خروجی ورد

**Export Word** یک `.docx` واقعی می‌سازد (نه یک فایل متنی با پسوند عوض‌شده):

- صفحهٔ جلد
- استایل Heading 1 / 2 / 3 ورد تا Navigation Pane کار کند
- فهرست مطالب
- شماره صفحه
- فونت و قطع انتخابی تو
- پاراگراف **RTL** فارسی / عربی، کد LTR مخلوط، ارقام فارسی در صورت فعال بودن

همچنین **export / import JSON** پروژه برای پشتیبان. کلید API از خروجی حذف می‌شود.

## امنیت

| چیز | کجا ذخیره می‌شود | داخل خروجی / گیت؟ |
|------|-------------------|---------------------|
| پیش‌نویس کتاب | IndexedDB مرورگر | فقط اگر خودت JSON بگیری |
| کلید API | مرورگر، با کلید دستگاه مخفی می‌شود | **هرگز** |
| تنظیمات موتور (آدرس، شناسهٔ مدل) | local storage مرورگر | داخل `.docx` نیست |

فایل `.env` با کلید زنده را commit نکن. کلید را داخل متن فصل نگذار.

## رفع اشکال

| مشکل | کار |
|------|------|
| `spawn vite ENOENT` | بخش [ویندوز](#ویندوز-خطای-spawn-vite-enoent). از `npx vite dev --host 0.0.0.0 --port 8080` استفاده کن |
| `npm install` قطع یا ناقص | `node_modules` و `package-lock.json` را پاک کن و دوباره نصب کن |
| پورت ۸۰۸۰ اشغال | `npx vite dev --port 5173` |
| Test connection شکست | Base URL باید به `/v1` ختم شود، شناسهٔ مدل با سرور یکی باشد، کلید معتبر باشد، سرور محلی روشن باشد |
| Ollama: مدل پیدا نشد | `ollama list` — همان نام را عیناً وارد کن |
| LM Studio: connection refused | Local server باید داخل LM Studio روشن باشد (پورت ۱۲۳۴) |
| جواب خالی / تایم‌اوت | تایم‌اوت را بالا ببر، max tokens را کم کن، یا مدل کوچک‌تر بگذار |
| محدودیت نرخ | requests/minute را روی ارائه‌دهنده تنظیم کن، صبر کن، یا مدل پشتیبان اضافه کن |
| کتابخانه بعد از رفرش خالی | داده مال همان پروفایل مرورگر است. site data را پاک نکن. از JSON پشتیبان بگیر |
| فارسی در ورد چپ‌چین است | زبان کتاب را فارسی بگذار و RTL / ارقام فارسی را در Press روشن کن |
| AI Engine در اولین اجرا نیست | از هدر کتابخانه **AI Engine** را باز کن |
